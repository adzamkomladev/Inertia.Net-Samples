# Hosting decisions and research

Reviewed 2026-10-12 against Microsoft documentation, Aspire documentation and the installed package APIs.

- **Worker:** the .NET Worker template uses `Microsoft.NET.Sdk.Worker` and top-level `Host.CreateApplicationBuilder`. Hosted services receive cancellation and graceful shutdown from the Generic Host. Queue consumption and TickerQ scheduling belong here. TickerQ 10.4.0's installed API supports `UseTickerQ(IHost)`, so a web host is unnecessary. Sources: [Worker services](https://learn.microsoft.com/en-us/dotnet/core/extensions/workers), [Generic Host](https://learn.microsoft.com/en-us/dotnet/core/extensions/generic-host), [TickerQ configuration](https://tickerq.net/docs/guides/configuration).
- **Realtime:** SignalR requires ASP.NET Core's web host. Its top-level entry point builds a focused web application with cookie authentication and hub endpoints. Source: [SignalR hosting and scaling](https://learn.microsoft.com/en-us/aspnet/core/signalr/scale?view=aspnetcore-10.0).
- **Affinity:** a Redis backplane distributes messages but does not remove connection affinity requirements for negotiation and fallback transports. MainApp and Realtime have distinct destination pools and cookies. YARP's `HashCookie` policy and `Redistribute` failure policy are configured for both. Sources: [SignalR scaling](https://learn.microsoft.com/en-us/aspnet/core/signalr/scale?view=aspnetcore-10.0), [YARP session affinity](https://learn.microsoft.com/en-us/aspnet/core/fundamentals/servers/yarp/session-affinity?view=aspnetcore-10.0).
- **Aspire:** AppHost defines resources and startup dependencies; ServiceDefaults provides host-agnostic telemetry and service discovery. Business code remains in a separate library. Database and Redis references supply runtime connections. Sources: [Service defaults](https://learn.microsoft.com/dotnet/aspire/fundamentals/service-defaults), [project resources](https://aspire.dev/integrations/dotnet/project-resources/), [PostgreSQL](https://aspire.dev/integrations/databases/postgres/postgres-host/), [Redis](https://aspire.dev/integrations/caching/redis/redis-host/).
- **YARP destinations:** separate Aspire project resources expose each process as a destination. The multi-destination cluster overload requires explicit `WithReference(endpoint)` calls for service discovery; verified against the installed Aspire.Hosting.Yarp 13.6.1 implementation and the live gateway. Source: [Aspire YARP integration](https://aspire.dev/integrations/reverse-proxies/yarp/).
- **Validation after extraction:** `AddValidation()` is called in the library that owns endpoint input models so .NET 10 generates their validation metadata there. The ASP.NET Core framework reference already supplies the generator; an extra validation package is redundant on this target. An invalid-signup integration test protects this behavior. Sources: [.NET 10 validation](https://learn.microsoft.com/en-us/aspnet/core/fundamentals/validation?view=aspnetcore-10.0), [NuGet pruning](https://learn.microsoft.com/en-us/nuget/reference/errors-and-warnings/nu1510).

The AppHost uses .NET 10's file-based application support: SDK, packages and properties are declared in `apphost.cs`. Stable `AddProject(name, projectPath, ...)` overloads locate each existing executable, without generated `Projects.*` types or app assembly references. The existing user-secrets identity is retained for persisted database credentials. Sources: [Aspire SDK](https://aspire.dev/get-started/aspire-sdk/), [file-based C# AppHosts](https://aspire.dev/integrations/dotnet/csharp-file-based-apps/).

File-based runs have no launch profile. The AppHost explicitly loads its user secrets and then reapplies environment overrides, keeping saved parameters available in both .NET and CLI launches. This avoids regenerating a database password when a persisted PostgreSQL volume already exists.

The library reference guard enforces the requested production dependency direction. Only integration test projects reference executable assemblies; executable code never imports another executable.
